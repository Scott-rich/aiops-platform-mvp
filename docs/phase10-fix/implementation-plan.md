# 第十阶段缺陷修复计划

依据上一轮独立复测；原压缩包和冻结源码完整保留，源代码改前快照见source-before-fixes.zip。实际数据库操作仅针对测试副本。

| 顺序 | 范围 | 修改与风险 | 验收 |
|---|---|---|---|
| 1 | incidents | 按相关服务/trace分页查证据；新鲜错误span阻止恢复。风险：历史关联行为、查询成本和实例替换语义 | 20,000条无关事件不改变根因；502 span不能resolved；原事件生命周期测试 |
| 2 | diagnosis/model | 原结构兼容；真实模型选择受证据约束，原文与规范化审计分开；无内部因果证据不猜机制/高置信。风险：旧缓存复用与小模型输出 | 原语义反例、旧报告读取、实际模型至少有效一次及unknown对照，预算/错误回退 |
| 3 | acceptance | 修解释器符号链接、显式结果契约与完整输入哈希。风险：历史结果格式差异 | 空/未知/矛盾结果失败；真实CLI子进程验证；已支持的结果格式不误拒 |
| 4 | storage | 已有库变更前一致备份，备份失败禁止迁移。风险：WAL与并发初始化、性能 | 旧库副本迁移、恢复表/行/模式、重复初始化不无限备份、原库未动 |
| 5 | benchmark | 质量场景完整遥测；区分健康/无注入但SLI异常；观测耗时透明 | 实际HTTP重复测试，错误对照显式blocked/failed，不能只改标签消除失败 |
| 6 | Flink性能 | 新完整Kafka→Flink→告警→持久化多速率实验，真实数据、耗时与资源。风险：窗口控制时标与容量 | 输入/窗口样本匹配、输出/延迟/lag/CPU/RSS实测JSON/CSV；强制水位明确标记 |
| 7 | 终测与打包 | 模块稳定后冻结，完整回归、原生链路、模型、故障、恢复、证据、更新文档 | 保留每次失败和修复；按实际结果标完成，原历史文件保留 |

环境探测：无Docker/Podman可执行文件、无Docker socket，用户命名空间创建被内核拒绝。因此此环境不能完成容器部署实测，不能用原生进程替代Docker验收。其他可验证功能继续完成。
