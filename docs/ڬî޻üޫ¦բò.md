# v0.2 验证记录

验证日期：2026-10-20。执行环境为Python3.12.14；应用容器定义使用Python3.11，PyFlink使用匹配的独立镜像。本文记录实际已运行的内容，并将容器验收与本机验证区分。

## 1. 优化版真实故障周期

运行命令：

```bash
python -m scripts.verify_optimized --output examples
```

脚本通过API操作独立Uvicorn进程，模拟服务使用真实本机TCP/HTTP互调。默认约3RPS，35秒健康、30秒支付503错误、45秒恢复，共110秒。检测采用Python快速通道和窗口对照规则；没有运行Kafka、Flink引擎或真实LLM。

| 观测项 | 本次实际结果 |
| --- | --- |
| 控制台 | HTTP200，返回平台页面 |
| 原始事件 | 3946条 |
| 原始告警 | 18条：3条快速、15条窗口 |
| 关联事件 | 1个availability事件，候选服务payment |
| 影响服务 | gateway、order、payment |
| 最终事件状态 | resolved |
| 报告版本 | 4版：preliminary、enriched、enriched、resolved |
| 本地通知箱 | 2条：打开1条、恢复1条 |
| 隔离记录 | 0条 |
| 模拟服务遥测发送失败 | 四服务均为0 |
| 快照及引用 | 4份报告哈希均有效，支持/反对证据引用均存在 |

时间以脚本开始后的秒数记录：

| 里程碑 | 时间 |
| --- | --- |

| 首次观察事件、初报及打开记录 | 36.81s |

按API轮询里程碑，注入到初报约1.62秒，清除到确认恢复约20.45秒。采样约0.5秒，结果受本机负载与调度影响，不能视为延迟SLA。恢复时三个受影响服务各有30个最近10秒健康样本，最新数据均满足5秒新鲜度要求；最大采样间隔分别约652ms、644ms、605ms。

`optimized-run.json`的8项检查全部为true：控制台可访问、仅一个可用性事件、事件恢复、一次打开记录、一次恢复记录、报告包含三个阶段、哈希与引用有效、遥测失败为零。`storage.reports=0`是旧基线报告表计数，v0.2报告存于`report_versions=4`，不是缺少报告。

产物为`examples/optimized-run.json`、`examples/optimized-report-versions.json`和`examples/optimized-report.md`。完整过程和报告均已导出。最后恢复报告的快照达到1800条上限，`truncated=true`，不能视为全部原始数据。它冻结的告警数为15；稍后到达的3条历史窗口告警使实时事件计数达到18。这属于预期历史补入，不是恢复报告被修改。

## 2. 自动测试与静态检查

执行入口为`python -m unittest discover -s tests -v`。最终54项测试全部通过，耗时22.487秒。覆盖范围包括：

- 四服务HTTP调用、trace/父子span、错误和延迟传播、清除故障与控制标签隔离。
- 窗口阈值、稳定告警ID、事件去重，以及快速连续5xx的重置和重复处理。
- 批量入库、异常数据拒绝、跨服务证据关联、不可变快照和哈希校验。
- 事件合并/隔离、实例边界、历史告警重放、恢复样本新鲜度及中断后不误恢复。
- 初报、补证、恢复版本；模型最多一次尝试、受控响应的引用校验和失败回退；慢任务隔离、全量活动事件调度和公平轮询。
- v2增量聚合的去重、合并、直方图边界和溢出行为；对照精确规则。
- API事件/报告查询、Markdown导出、校验、404及故障控制参数边界。

模型测试使用受控响应，不是实际模型能力评估。ASGI集成测试检验路由与调用逻辑；上节110秒运行另行验证真实TCP链路。Python源码编译和Compose YAML结构检查也属于本地静态检查，不代表镜像能成功构建。
