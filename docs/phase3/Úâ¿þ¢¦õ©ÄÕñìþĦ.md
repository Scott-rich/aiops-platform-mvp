# 第三阶段部署与复现

本阶段在原项目上增加RCA模块、报告附件、只读接口和控制台。没有新增Python依赖、数据库迁移或远程管理入口；保留原API及历史报告。运行状态和未通过项目以《第三阶段验收报告》为准。

## 本地运行

在Linux/WSL项目根目录，使用Python3.11或3.12：

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m scripts.local_platform --data-dir data-phase3
```

访问 http://127.0.0.1:8000 。四个HTTP服务产生真实请求、span和日志；这个启动模式使用本地Python检测，不包含Kafka/Flink。新报告展示依赖图、直接异常服务、受影响服务和多个候选根因。`unknown`是正常的证据不足结论。

原生分布式部署步骤见 `infra/NATIVE_TESTING.md`。本次环境没有Docker/Podman，不能把Compose静态检查称作容器启动验证。推荐独立Linux开发环境；原生测试使用Java17、Kafka3.9.1、PyFlink1.20.3和Kafka Connector3.3.0-1.20。首次准备需要网络和磁盘，包内不包含下载的JAR及模型权重。

```bash
python -m scripts.bootstrap_native --runtime-dir /tmp/aiops-native-runtime
/tmp/aiops-native-runtime/venv/bin/python -m scripts.native_streaming \
  --runtime-dir /tmp/aiops-native-runtime --output artifacts/my-phase3-native
```

输出目录必须是新的。该脚本实际检查Kafka/Flink、异常输入、重复/乱序、checkpoint恢复，并注入HTTP故障，核验RCA角色、证据哈希和拓扑API。所有进程清理结果记录在result.json；失败不会抹去现场。

## 自动化测试

```bash
PYTHONPATH=.:flink python -m unittest discover -s tests -v
PYTHONPATH=. python -m unittest tests.test_rca tests.test_rca_evaluation \
  tests.test_rca_reporting tests.test_rca_ui -v
PYTHONPATH=. python -m scripts.evaluate_rca --output artifacts/my-rca-evaluation
PYTHONPATH=. python -m scripts.verify_optimized --output artifacts/my-phase3-http
```

UI契约测试需要Node.js；没有Node时相关跳过应明确计数。PyFlink执行图测试需要独立运行时和连接器，完整验证时使用 `/tmp/aiops-native-runtime/venv/bin/python` 并配置 `AIOPS_SOURCE_BRIDGE_JAR`、`AIOPS_KAFKA_CONNECTOR_JAR` 指向bootstrap实际产物。不要拿默认跳过的重型集成入口计为通过；原生脚本单独实测。

`verify_optimized`约110秒，含35秒正常流量、30秒故障、45秒恢复；是真实HTTP，本地Python检测，没有Kafka/Flink或LLM。`evaluate_rca`是12个固定合成算例，不是生产准确率或性能压测。可追加 `--archived-report artifacts/native-attempt-04/actual-http-report.json` 重放旧真实报告；未标注重放不计准确率分母。

## 接口与兼容性

| 接口 | 作用 |
| --- | --- |
| GET /reports/{report_id}/rca | 原报告接口对应的冻结RCA |
| GET /report-versions/{report_id}/rca | 渐进式报告版本的冻结RCA |
| GET /incidents/{incident_id}/topology | 最新报告依赖图、证据集和完整性检查 |
| GET /reports/{report_id}/verify | 原有检查加RCA哈希、引用及证据集检查 |
| GET /report-versions/{report_id}/verify | 同上，针对不可变版本 |

旧报告没有RCA时仍可读取，RCA专用接口返回404，校验字段为null；不临时改写历史结果。有RCA但结构/引用损坏时专用接口返回409，校验接口返回明确false。哈希是内容一致性检查，不是外部签名。现有incident的root_anchor/candidate_service仍是关联事件的线索，真正的多候选诊断位于report.rca.candidates，不能把旧锚点字段当作已确认根因。

## 数据与故障边界

修改前备份位于 `backups/phase2-code-before-phase3.zip`。新字段写入新报告版本；未删除或重建旧表。保留实际失败日志和损坏数据库作取证，不自动REINDEX、删除或覆盖故障库。运行中SQLite应通过backup API备份，不只复制主文件。本阶段尚未解决数据库损坏原因，出现DatabaseError时worker停止且不提交失败批次；不要在损坏目录上反复重启或声称自动恢复。

证据分页、归档及完整性扩展是后续第八阶段任务；当前快照存在数量上限，RCA记录截断和不确定性。控制台最多显示30节点/60边并提示裁剪，JSON保留当前快照内的完整图。没有真实浏览器视觉验收，已执行的是Node DOM契约和HTTP返回检查。

模型默认不配置，继续规则诊断。第二阶段真实模型诊断仍未通过验收；本阶段只测试历史/已校验模型观点整合，不再启动真实模型调用。密钥只用环境变量，不写入代码、示例或日志。平台仍只用于本地隔离研究，不自动执行处置建议。
