## 实际执行与数量

最终回归：**270通过、0失败、10跳过**，共280项；新增单元测试24项全部通过。跳过包括1个原生Kafka/Flink集成、1个真实模型集成和8个PyFlink专属测试。

主测HTTP 28通过/0失败，Kafka 12通过/0失败；慢消费 6通过/0失败；真实进程中断及输入/覆盖保护6通过/0失败。新建测试数据库13个全部quick_check=ok。

本轮实际使用 `/tmp/aiops-phase5-venv/bin/python`，下列命令在项目根目录执行；生成目录随后复制至artifacts/phase6对应子目录。

```bash
python -m unittest tests.test_benchmarks -v
python -m unittest discover -s tests -v
python -m scripts.benchmark_platform --output /tmp/aiops-phase6-accepted --kafka-home /tmp/aiops-phase5-kafka/kafka_2.13-3.9.1
python -m scripts.benchmark_platform --component kafka --output /tmp/aiops-phase6-slow-final --kafka-home /tmp/aiops-phase5-kafka/kafka_2.13-3.9.1 --kafka-rates 50,150,300 --duration 3 --repeats 1 --consumer-delay-ms 350
python -m scripts.verify_benchmark_controls --output /tmp/aiops-phase6-controls-final
python -m scripts.compare_benchmarks artifacts/phase6/accepted/result.json artifacts/phase6/slow-final/result.json --output artifacts/phase6/configuration-comparison.json
```

比较命令退出2为预期：相同环境、源码和协议，但消费延迟/时长/重复次数不同，不生成混用配置的提升百分比。主测每档4秒、每档重复2次，总耗时 83.72秒（含启动、故障验证和清理）。

## 失败、阻塞与恢复边界

- 首轮main存在10个负载器跳过；第二轮final因旧lag采样竞态有1个检查失败。已修复并保留全部原始记录。
- 早轮资源采样受PID命名空间影响为null，不作为CPU/RSS证据；修复PPid/NSpid映射后，accepted/slow-final所有资源检查通过。
- 真实模型服务未配置，本轮真实调用数0；模型耗时、token与费用未测得，保持null。费用汇总和异常路径有单元测试，不能替代真实模型验收。
- Flink引擎吞吐、checkpoint恢复和Docker/Compose未重跑；本轮Kafka是Python处理路径。
- 历史SQLite损坏根因仍未解决；本轮新库完整性检查通过，不据此宣称历史问题或高可用已解决。
- 原阶段ZIP缺少中央目录的情况与开发修复见开发验证记录；当前交付ZIP重新生成并独立校验。
