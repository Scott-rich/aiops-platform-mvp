基于本会话第五阶段成品增量升级。已核对源码、requirements、Compose、SQLite、第五阶段验收及现有evaluate_detection/evaluate_rca/verify_llm/verify_faults脚本。原phase5压缩包与source-before-phase6.zip保留，不迁移历史数据库。

| 状态 | 当前能力 |
| --- | --- |
| 已实现 | 真实四服务HTTP、Kafka消费持久化、固定/动态检测、RCA、十类故障场景、规则回退 |
| 部分实现 | 700合成窗口固定/动态对照、12个RCA算例；已有模型调用元数据/费用估算，缺少统一评估报告 |

| 本轮环境 | Python/Java17/Kafka可用；没有Docker/PyFlink、没有LLM配置；不将前轮结果当本轮实测 |

## 顺序、文件、风险和验收

1. benchmarks/metrics.py、resources.py：统计定义、缺失值、分母、Linux进程采样；以明确数列/时钟/失败情形测试。
2. benchmarks/http.py：复用第五阶段专属四服务运行器，分档请求和事件入口负载、故障检测延迟、真实trace RCA；测试不调用模型，不接受外部地址。
3. benchmarks/kafka.py、runtime.py：专属broker和consumer线程，真实事件创建→持久化完成延迟、producer确认、lag采样、限速消费者追赶；有界队列、超时与清理。单机小规模结果不外推生产容量。
4. benchmarks/model.py：汇总每次attempt的耗时与usage/cost，避免报告复用重复计费；未知usage或单价保持null；可显式启用既有真实模型验证命令，最多一次HTTP尝试。
5. scripts/benchmark_platform.py、compare_benchmarks.py：统一JSON/CSV、环境/源码/配置哈希、可比性条件、报告、独立回放；新目录禁止覆盖。
6. 实测多档速率与有限重复、全量回归、异常/清理验证，交付验收报告。HTTP请求耗时、遥测接收时间、durable completion、事件时间检测延迟分别标识。

风险：测量自身有开销，SQLite和本机资源会限制吞吐；并发达到上限必须记录跳过，不能把目标速率写成实测速率。请求失败保留在统计分母，缺失延迟/模型usage不可填0。数据集标签不进入模型/算法输入。初次模型审计表初始化仍使用已有备份流程，只在新测试库中执行。源代码不做无关重构。
