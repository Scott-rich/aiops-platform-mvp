# 第九阶段基线审计与实施计划

基线为用户提供的第八阶段压缩包；保留原包、历史数据和既有接口。本阶段不对历史库执行迁移或清理。原始源码备份见本目录 `local_platform.before.py`，原包 SHA-256 见 `source-sha256.txt`。

| 项目 | 状态与依据 | 缺口/风险 |
|---|---|---|
| 配置 | LLMConfig、DetectionConfig 有范围检查，其他配置分散在各进程和 Compose；示例文件存在 | 缺少不泄露密钥的统一启动前检查；并非所有变量集中管理 |
| 日志 | 多数模块使用 Python logging，worker 有级别设置 | 日志格式和级别未完全统一；不应承诺全链路结构化日志 |
| API | FastAPI/Pydantic 参数验证，SQLite 错误 503，证据接口分页 | 未有统一格式的全局错误响应，不宜破坏旧客户端 |
| 存储 | SQLite WAL，文件锁；phase7/8 增量迁移并在迁移前创建备份 | 初始基础表的 CREATE IF NOT EXISTS 先于增量备份；不是通用版本化迁移框架 |
| 健康与生命周期 | Compose 配置健康检查、依赖关系；本地 launcher 管理并停止子进程 | Docker 本轮不可用，不能将静态检查视作部署验证 |
| 安全 | Compose 主机端口绑定 loopback；模拟器 token 可配置；密钥来自环境 | API 和故障控制无用户认证；容器内部不是可信隔离边界；禁止公网或不可信网络使用 |
| 依赖 | 顶层固定版本；独立模型依赖清单 | 传递依赖和镜像未完全锁定，无离线可复现保证 |
| 测试 | 项目含单元、集成、故障与验收脚本；历史报告记录此前原生 Kafka/Flink 验证 | 本轮结果必须重新记录；真实模型与 Docker 不可默认视为已验证 |
| 密钥隔离 | 启动器移除已知模型密钥和代理 | 非已知供应商密钥可能继承到模拟器子进程 |

实施：1. 先运行基线测试；2. 增加只读配置预检并复用已有配置校验，检查密钥传递和执行边界；3. 限制模拟器继承的通用敏感环境变量，保留已有显式控制令牌；4. 增加对应自动化测试及独立启动验证；5. 完整回归、记录阻塞与依赖，更新文档。无数据库结构或外部配置修改，出错可恢复备份文件。预检不是认证系统、依赖安全审计或 Docker 运行证明。
