# 第九阶段工程化验收与剩余工作

## 结论

本轮完成一批可运行、可测试的工程化增量；**第九阶段整体仍为部分完成**。没有远程身份认证及权限控制，配置和日志尚未全平台统一，Docker Compose 与真实模型未在本轮验证，不能宣称生产就绪或高可用。此前 Kafka/Flink 实测仅是第八阶段历史记录，本轮没有重复运行。

## 改动与原因

| 文件 | 改动和验证 |
|---|---|
| `scripts/preflight.py` | 新增只读配置预检；复用 LLM/检测设置校验，检测安装版本、DB 超时和安全边界；不输出配置值。6 项专项测试和实际命令验证。只覆盖列出的配置，不是全部参数校验。 |
| `scripts/local_platform.py` | 本地 `.env` 额外读取明确列出的存储/证据配置；子进程过滤常见敏感变量名，保留模拟器控制令牌；旧的环境变量优先规则不变。原文件备份见 `local_platform.before.py`。 |
| `tests/test_phase9_engineering.py` | 六项测试，覆盖配置无效、回退、敏感值不出现在检查输出、子进程过滤、文件权限、优先级与缺少依赖。 |
| `requirements-lock.txt` | 由干净 Python 3.12 环境解析结果生成的全部运行依赖版本快照。没有包哈希；需要平台相容性验证。 |
| `.github/workflows/tests.yml` | CI 中安装锁文件、预检和跑回归；未连接 GitHub 执行。 |
| `.gitignore`、`.dockerignore`、`.env.example` | 加入常见密钥/本地环境文件忽略规则和日志配置说明；修改前副本见 `config-before/`。忽略规则不自动移除已经追踪的数据。 |
| `README.md`、`docs/phase9/` | 更新当前状态、部署、风险和实测记录；保留此前的历史报告。 |

没有更改数据库结构、已有 API 响应或历史数据。原 ZIP 中 1,643 个文件逐一比较 CRC32：只有 `.dockerignore`、`.env.example`、`.gitignore`、`README.md`、`scripts/local_platform.py` 内容改变，无缺失；详细结果 `artifacts/phase9/baseline-comparison.json`。CRC32 是变更检查，不是密码学完整性证明；原包 SHA-256 保存在 `source-sha256.txt`。

## 执行命令

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_phase9_engineering.py' -v
python -m scripts.preflight --env-file .env.example
python -m pip check
python -m unittest discover -s tests -v
python -m venv /tmp/aiops-phase9-venv
/tmp/aiops-phase9-venv/bin/python -m pip install -r requirements.txt
/tmp/aiops-phase9-venv/bin/python -m pip freeze > requirements-lock.txt
/tmp/aiops-phase9-venv/bin/python -m pip check
/tmp/aiops-phase9-venv/bin/python -m unittest discover -s tests -v
python -m venv /tmp/aiops-phase9-lock-venv
/tmp/aiops-phase9-lock-venv/bin/python -m pip install -r requirements-lock.txt
/tmp/aiops-phase9-lock-venv/bin/python -m pip check
/tmp/aiops-phase9-lock-venv/bin/python -m unittest discover -s tests -p 'test_phase9_engineering.py' -v
python -m compileall -q app scripts simulator flink tests
```

本地 HTTP 以临时目录启动 `python -m scripts.local_platform --port <临时端口> --base-port <临时端口> --data-dir <临时目录> --no-load`，真实 HTTP 校验后发送 SIGTERM；实际结果记录中不含实时凭据。Compose 仅用 Python YAML 解析并检查显式端口，非 `docker compose config`。

## 下一步与环境依赖

1. 在有 Docker 的隔离机器使用锁定的容器构建并跑真实 Kafka/Flink、重启和恢复验收；不要将本轮静态解析当作部署通过。
2. 在经授权的兼容模型服务配置下运行独立真实模型验收；费用与凭据由执行环境提供，严格遵循预算。
3. 若需要远程访问，先设计并测试认证、授权、CSRF 防护、审计和网络隔离，再开放高风险端点。
4. 进一步统一配置和日志、实现带备份和版本记录的迁移工具、校验文件密钥与供应链依赖，并在真实 CI 运行。锁文件需要在目标操作系统和 Python 版本验证，容器镜像与依赖哈希目前尚未锁定。
5. 完整验证停止/恢复、权限以及不同系统上从锁文件安装；本阶段不宣称完整第九阶段验收或最终平台验收通过。
