# 第四阶段交付验收报告

交付范围：用户提供的第三阶段工程之上的**异常检测算法优化**。默认固定阈值保持兼容，动态模式已实现并完成真实Kafka/Flink运行与checkpoint恢复验证；这不代表整个九阶段平台已验收。

## 失败记录、备份及边界

- 嵌入式Flink第一次脚本将dict直接以PICKLED_BYTE_ARRAY交给Java collection source，发生HashMap转byte[]失败；修正为字符串source后由Python map反序列化，第二次真实运行通过。第一份失败日志保留。
- 自适应恢复测试第一次把暖机数据放在前一天23点而故障放在00点，触发正确的独立时段暖机，测试索引假设失败；该恢复专项测试改成24小时桶后通过。独立时段暖机原测试仍保留。
- Kafka初始串行下载较慢，停止后使用HTTP Range并发续传；组装后仍通过Apache公布SHA-512验证，再运行原bootstrap。下载不是部署验证，原始日志保留。
- 原始722个文件均保留，修改14个，其余708个逐文件内容一致；未修改历史SQLite、未做迁移、未删除历史报告。修改前配置与源码备份见`修改前源码与配置备份.zip`，原包哈希和文件清单见backup.json及changed-source-files.json。
- 未启用或调用真实LLM；无外部API计费。模型阶段历史未验收状态保持。
- 动态实现通过本轮功能验证，但冷启动污染、长期阶跃/季节变化、缺少其他服务基线、输入异常量超出开发规模等限制见部署指南。
- Docker不存在于本次环境，Compose仅静态解析，未宣称容器部署成功；原生测试需要Linux、Java17、uv及首次联网下载。虚拟环境和大型运行时不打入源码包。
- 原有SQLite损坏的根本原因仍未查明。本轮有限测试未出现同类错误，不能据此宣布已修复存储可靠性或高可用。
