源包SHA-256及修改前源码记录见`baseline.json`、`source-before-phase7.zip`；逐文件差异哈希见`changed-files.json`。最终业务源码与保留的最后一次真实运行源码哈希一致，自动核对记录见`artifacts/phase7/acceptance.json`。

以上为单次本机隔离测试的观察值，不是SLO、吞吐容量或统计性能结论；部分回归与集成同时运行。测量起止定义由各JSON字段和脚本给出。Kafka恢复本次由测试监督进程重启worker **1次**，明确计入恢复耗时。消费组身份失效后安全退出并重放，不宣称进程无重启恢复。

- Kafka：broker停机时发送返回明确异常，已确认的150条积压事件在重启后仍可读取；156条积压排空。把整个日志offset重置到0并重放，events/alerts/incidents/DLQ/通知数量保持不变。
- 数据库：注入测试拥有的跨进程访问锁故障；API返回503，worker三次尝试后失败退出，已提交offset停在161；释放后重启worker追赶。该实验不是磁盘故障或断电验证。
- Flink：运行Kafka3.9.1、Flink1.20.3、connector3.3.0-1.20、3分区/并行度2，校验checkpoint、TaskManager重启及未结束窗口20个样本恢复。还验证乱序、迟到、重复/冲突/毒消息、Python/Flink规则结果和真实HTTP故障证据。本轮首次25项亦通过（`flink-native`）；worker超时修复后再次运行最终25项。
- 平台：worker与查询API重启，历史报告逐字段一致，snapshot/RCA哈希与证据引用均校验通过。随后用真实墙钟连续发送健康指标，实际观察open→recovering→resolved，恢复通知只保存一次。
- SQLite异常退出：子进程在未提交事务中`os._exit`，重开后回滚；另一个子进程提交后退出，数据保留；最终integrity_check为ok。
- 模型：回环HTTP端点故意延迟，发生request_timeout后生成包含5条真实存储证据的规则报告。只收到1次HTTP请求；重开数据库后仍不重复调用。端点是明确标记的超时桩，没有执行模型推理，没有外部API费用。

## 实际执行命令

均从项目根目录执行。这里保留本轮解释器及运行时路径；干净环境的可移植安装方式见[恢复指南](可靠性部署与恢复指南.md)。本轮命令输出从临时目录在进程退出后完整复制到对应artifacts目录。

```bash
/tmp/aiops-phase7-native/venv/bin/python -m unittest discover -s tests -v

/tmp/aiops-phase5-venv/bin/python -m scripts.bootstrap_native --runtime-dir /tmp/aiops-phase7-native
/tmp/aiops-phase7-native/venv/bin/python -m scripts.native_streaming \
  --runtime-dir /tmp/aiops-phase7-native --output /tmp/aiops-phase7-flink-final

  --kafka-home /tmp/aiops-phase5-kafka/kafka_2.13-3.9.1 \

  --source artifacts/phase6/accepted/http/runtime/data/aiops.sqlite3 \

```

## 未解决问题、外部依赖与下一阶段

1. 没有可用Docker运行时，未实际运行Compose；不能把配置更新算成容器部署完成。
2. 没有真实模型服务配置，未验证真实模型诊断质量、耗时或费用；超时桩不计为模型推理验收。阶段2仍需有效的OpenAI兼容地址、模型及凭据（环境变量）。
3. 历史SQLite损坏原因仍未知；本轮新库与旧库副本完整性通过，不表示历史损坏已修复。未自动删除/重建旧库。
4. 采集端没有磁盘outbox；未确认消息可能丢失或结果未知。Fast状态容量淘汰会丢失部分序列；本地固定窗口游标仍可能跳过停机期间窗口。详细边界见恢复指南。
5. 单broker、单SQLite、本地checkpoint；未覆盖磁盘丢失、整个JobManager重启、跨机故障切换或多副本高可用。使用Java17/Linux即可执行本轮测试，不要求GPU。
6. PyFlink单元进程结束时有两条Java gateway管道ResourceWarning；未计为失败，但未将其宣称消除。真实native和可靠性验收均记录所有子进程已停止。
7. 证据查询/报告仍有原有数量上限。**下一阶段为阶段8**：分页和筛选、明确证据集ID/总数/引用/截断、完整性哈希验证、历史报告版本比较、受控保留归档，先实现超过单页上限也能逐批读取完整证据的用例。

本阶段没有要求或使用新的真实API密钥；新增配置均走环境变量，源码敏感模式扫描未发现硬编码真实密钥。项目包保留源码、测试、文档、真实结果、失败日志和数据库验证副本；不附带可重建的Kafka运行日志段及Python缓存。
