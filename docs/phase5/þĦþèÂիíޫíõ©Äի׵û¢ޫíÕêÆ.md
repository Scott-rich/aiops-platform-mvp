## 实施顺序

1. simulator/faults.py、service.py：保留旧参数，增加 timeout/unavailable、可取消等待、按服务记录故障开始/结束；单测。
2. simulator/network.py、pressure.py：只允许回环 TCP 代理，资源压力默认禁用，Linux 子进程有 wall/CPU/AS 上限；验证清理。
3. simulator/scenarios.py、scripts/verify_faults.py：四个真实进程、HTTP 遥测、真实停止/重启、级联、重复乱序坏数据、JSON/CSV；逐场景验证。
4. scripts/verify_fault_kafka.py：独立 topic 的 pause/resume、真实 backlog/消费延迟和生产 wire parser/存储处理；无运行时明确 blocked。
5. 全量回归，更新 README、部署架构与验收报告，记录原始命令、数量、失败和环境限制。

## 风险和验收

所有测试目标为本次启动的隔离本机进程；不接受外部服务/任意 shell。压力仅显式选项启用，最多单进程、32MiB增量内存、25%单核占空比、10s；默认跳过。TCP 代理不更改宿主机网络规则。新目录禁止覆盖；异常和 Ctrl+C 均清理。故障标签与真实遥测分开，不能泄漏为 RCA 证据。每项有预期、实测和恢复断言；Kafka 不可用不记通过；不宣称第六阶段容量测试或高可用完成。
