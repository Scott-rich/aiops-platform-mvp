## 本轮发现并修复的问题

1. 首轮内存验收用ru_maxrss峰值差推断增量，因exec前历史峰值干扰导致误判。改为/proc/self/statm的前后RSS；保留峰值仅作参考。首轮失败保留在http-attempt-01，不计成功。
2. Kafka首轮已完成积压/消费/隔离，但共享窗口复核把两个service混在一个WindowAccumulator中，触发正确的分组保护。脚本已按service分组，并增加回归测试；首次失败记录保留kafka-attempt-01。
3. 网络代理改为每个请求方向数据块注入延迟，避免现有HTTP长连接绕过仅握手时延迟。
4. 早期运行中的result.json快照曾停留running；不据此推定终态。最终套件在清理后单独写入不可变completed.json，并在同一命令中读取验证后保存；终态证据明确。
