# 第十阶段：部署、接口与验收

## 范围

继续采用 Kafka → Flink → Python worker → SQLite/证据/报告 的链路，以及独立的本地 HTTP + Python 检测模式。没有改变事件协议、检测算法、数据库表、报告证据哈希和模型结构化输出要求；模型建议仍不能自动执行。第十阶段新增 API 请求边界、启动参数校验、运行日志、真实 readiness 和统一验收脚本。

## 本地环境

Python 3.12、Linux；本轮也使用独立 Python 3.11/Java17 原生流处理环境。虚拟环境不与项目数据混放。

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pip check
cp .env.example .env
chmod 600 .env
python -m scripts.preflight
python -m scripts.local_platform --data-dir data-local
```

`local` 模式保留现有控制台和客户端行为，仍只适合可信本机。JSON 日志默认启用，`LOG_FORMAT=text` 可切换；`LOG_LEVEL` 控制平台 API、worker 和本地检测器。模拟器自身日志/Java Kafka/Flink 日志仍是原有配置，不能声称全系统已经统一格式。

## 可选 API 权限

设置 `API_AUTH_MODE=token`，分别配置随机、不同的 `API_READ_TOKEN`、`API_CONTROL_TOKEN`、`TELEMETRY_INGEST_TOKEN`，每个 32–512 个 URL 安全字符。可在私有终端用 `python -c 'import secrets; print(secrets.token_urlsafe(32))'` 生成，切勿提交真实值。

| 令牌 | 权限 |
|---|---|
| READ | 所有 GET/HEAD 查询，包括可能包含敏感信息的原始证据 |
| CONTROL | 查询和写操作；目前写操作包括模拟故障控制与本地遥测 |
| INGEST | 仅 POST `/demo/ingest` |
| 无令牌 | token 模式下仅 GET `/live`（实现对该路径免认证，但其他方法没有对应路由） |

令牌以 `Authorization: Bearer …` 发送，不接受 URL 参数或 cookie。local launcher 自动向模拟器传递摄取令牌，并用读令牌检查 API 健康；API 读/控制令牌不会交给模拟器。token 模式的旧网页控制台不带 Authorization：请使用有请求头功能的 API 客户端，或在隔离部署中配置受控网关；不能因控制台 401 而关闭认证公开端口。

这是共享令牌的三类权限，不是多人账户/完整 RBAC、用户操作不可抵赖审计或生产 SSO。使用远程网络仍需要 TLS、网络访问控制、令牌轮换、速率限制及身份管理；Kafka/Flink REST 没有由这层保护。Compose 发布端口继续绑定 127.0.0.1，不进行公网发布。Origin 检查拒绝浏览器跨源写入，但 local 模式不能防止可信主机上的恶意进程或全部 DNS 重绑定风险。

## 健康、错误与资源边界

- `/live`：无数据库查询的存活探针；启动初始化失败时服务不会接收流量。
- `/health`：保留原接口；存储无法读取时返回 503。在 token 模式需要 READ/CONTROL。
- `/ready`：Kafka 模式沿用 Kafka/Flink/worker 检查并实际读取存储；local 模式必须有运行中的检测循环、最近成功 tick、未发生最新 tick 错误。默认允许成功 tick 最老 10 秒，可用 `LOCAL_READY_MAX_AGE_SECONDS` 在 1–120 秒内配置。
- 写请求先在 ASGI 边界累计检查，最多 1,000,000 字节，支持无 Content-Length 的分块请求；超过返回 413。读取整个 body 的截止时间默认 5 秒，`API_BODY_TIMEOUT_SECONDS` 范围 0.05–30 秒，超时返回 408。这是应用缓存边界，非内核/代理全部内存的上限；入口代理仍应设置请求大小和连接限额。
- 每个请求生成 `X-Request-ID`；不信任来访者提供的 ID。422 保留 `detail` 的 type/loc/msg，移除原始 input/ctx；授权错误为 401/403，配置错误为 503。未声明统一覆盖所有异常响应；原有 404/SQLite 错误结构保持。
- 请求日志只记录路由模板，不记录 query/header/body；已知敏感环境值和 Bearer/URL 凭证会脱敏，异常只记录类型和代码位置。它不是通用数据脱敏系统，不保证业务日志或第三方组件中的所有敏感内容都被识别。
- 配置层复用原有 LLM/DetectionConfig；`LLMConfig.from_env(environ)` 不修改进程环境。存储等旧模块仍有自己的防御性校验，未将所有配置重写成单一大类。

## 自动验收

在一个新输出目录执行，命令不会覆盖已有结果。不要在运行期间修改代码；runner 比较运行前后源码哈希，变动会导致失败。

```bash
python -m scripts.acceptance --output artifacts/my-local-acceptance
# 本地测试 + 可选小规模 HTTP 吞吐测量；是当前机器观察值，不是生产容量
python -m scripts.acceptance --output artifacts/my-local-bench --benchmark
# 全验收门禁：缺少外部环境会退出 2，而非伪装通过
python -m scripts.acceptance --output artifacts/my-full-gate --require-full
```

默认运行 unittest、真实 HTTP 权限与生命周期、五进程联调、超量证据分页/归档、动态/固定检测对照、RCA 合成案例评估。`completed.json` 是不可变终态，`result.json` 为进度；两者含每条命令、退出码、耗时、机器可读文件哈希、环境与源码哈希。默认退出 0 仅表示本地门禁通过；`status=partial`、`full_acceptance=false` 仍明确标出未验证的外部门禁。测试跳过数量不会伪装为通过。

原生运行（需网络、Java17、uv、可用磁盘和内存）：

```bash
python -m scripts.bootstrap_native --runtime-dir /tmp/aiops-native
/tmp/aiops-native/venv/bin/python -m scripts.native_streaming \
  --runtime-dir /tmp/aiops-native --output artifacts/my-native-run
# 或加入统一 runner
python -m scripts.acceptance --output artifacts/my-native-acceptance --native-runtime /tmp/aiops-native
```

真实模型单独 opt-in：`scripts.verify_llm` / `acceptance --real-model` 使用配置的兼容服务；无配置明确 blocked；`--local-model-file` 和 `--model-python` 可使用真正的 GGUF CPU 推理。模型输入/输出、超时、成本和证据约束沿用第二阶段设计；真实推理成功不证明 RCA 正确或模型适用于生产。详情见本阶段实际验收报告。

Docker 环境仍是独立门禁。当前统一 runner 不自动管理 Docker 栈，明确标为未执行；不因主机有 Docker 或 YAML 合法而通过。升级环境应先备份数据库、保留 WAL/SHM 和 checkpoint，再依原指南部署，不要执行 `down -v` 清空数据。
