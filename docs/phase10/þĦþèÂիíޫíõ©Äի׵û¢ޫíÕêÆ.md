# 第十阶段：最终联调与验收计划

第十阶段对应原任务的最终联调、完整测试与验收，不将第九阶段剩余缺口视为已完成。本轮以 phase9 交付为基线；源码与配置备份 `source-before-phase10.zip`，SHA-256 清单 `baseline.json`。冻结基线回归结束后再修改代码。历史数据库、配置与报告保留，仅在临时目录/副本做验证。

1. 配置与启动：复用 LLM/动态检测配置，消除预检借用 unittest.mock 修改进程环境的方式；统一运行参数校验、日志配置；liveness 与依赖 readiness 分离。本地 readiness 必须检查近期成功 tick 和存储可读。
2. API 边界：现有接口保留；遥测请求在读取时限流到 1 MB；可选 read/control/ingest 三类 Bearer 令牌、拒绝跨源写入、返回请求 ID，422 不回显原始输入。默认 local 仅适用于可信 loopback 环境。令牌不是多人登录/完整 RBAC，也不保护 Kafka/Flink 管理接口。
3. 验收自动化：用独立进程、专属输出目录、退出码及机器可读结果运行全量回归、证据分页/旧库副本升级、RCA/检测对照、HTTP 性能及可用环境内的原生流处理与恢复。未提供运行时或模型的项目明确 blocked，不计入通过。
4. 清洁环境安装、真实 HTTP 鉴权/就绪/异常输入验证、文档与包校验；修复测试失败并保留失败日志。最终产物提供逐文件变更、实际命令和通过/失败/跳过数量。

风险：新增 API 权限模式需由调用者选择并配置令牌；token 模式旧控制台需要带 Authorization 的客户端/网关，不能悄悄降级。配置校验可能使原先无效设置在启动时报错；部署前执行 preflight。无数据库迁移、无自动处置 LLM 建议、无公网发布。Docker 不存在，原生链路即使成功也不代表容器部署通过。
