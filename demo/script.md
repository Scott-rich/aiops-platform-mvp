# 五分钟演示逐字稿与录制说明

最终 MP4 对应 `p4-video-02` 的真实进程输出。业务服务是合成服务；HTTP 请求、故障控制、告警、事件、GGUF 推理与报告查询均在录制期间实际执行。这不是 Kubernetes、Chaos Mesh 或真实业务基准，也没有用预录响应冒充实时输出。录像无配音，以下是可直接朗读的中文稿；画面已有中文阶段提示。

## 0:00—0:30：问题与边界

“这是一个面向微服务的智能运维研究平台。它关心的不只是生成一份看上去合理的报告，而是报告里的每一条证据能否被追溯，模型不知道时是否允许弃权。现在启动的是本地演示：四个合成业务服务通过真实 HTTP 连接。屏幕上的就绪状态来自刚启动的进程，不是预先准备的文本。今天展示故障、告警、证据和恢复这条链路；真实集群的验证状态会在最后单独说明。”

## 0:30—2:00：故障、告警与关联

“现在通过服务自己的故障控制接口，让 payment 返回错误。这个操作模拟业务故障，并不等同于基础设施混沌实验。后台继续发送请求，服务产生真实的日志、请求和链路记录。我们等待检测窗口积累，而不是在故障开关打开的瞬间直接写入一条假的告警。

现在读取告警列表。可以看到服务、规则和告警 ID。一个底层故障可能影响上游，所以告警数量不能直接等于故障数量。平台接着把相关观测组织成事件。这里根据已知演示目标选择 payment 的可用性事件，再读取它的报告版本。

版本记录很重要。早期报告只包含当时已经收到的证据，之后的观测进入新的版本。新版本不会覆盖旧报告。演示会明确取得版本号最大的报告，不依赖列表碰巧采用哪一种排序。我们稍后核验的是保存下来的证据，而不是用当前数据库重新拼出一份过去的报告。”

## 2:00—3:30：真实模型与证据核对

“现在从这次事件的真实记录中选择同一条 trace 的证据，调用本地 GGUF 模型。模型只能返回协议允许的证据键，再由系统映射回事件。屏幕显示的是模型实际生成的原文。它可以选择候选，也可以弃权；无论哪一种，都不由演示脚本替换成预设答案。

这次小模型选择了弃权。它没有提供有效的根因候选，所以不能把规则 RCA 的结果算到模型名下。接下来的校验检查完整证据集、快照、RCA 哈希与引用的一致性。这里的通过表示文件和引用能相互核对，不代表对业务根因已经获得了外部因果证明。

现在清除合成故障，并继续发送健康请求。清除开关不是恢复的充分条件。平台仍然需要新鲜的服务指标、完整的采样覆盖和持续健康的观察时间。为了演示好看而直接把事件状态改成恢复，会破坏我们刚才建立的证据链。”

## 3:30—4:30：恢复与报告版本

“这里再次读取事件状态。只有平台根据新证据给出 resolved，才说明这次演示观察到了恢复；open 或 recovering 都不能被口头改成成功。随后读取全部报告版本，并明确选择最新版本。

现在再次核对证据哈希与引用。演示脚本要求目标 payment 事件真实恢复，同时要求这些一致性校验通过；否则它保留失败目录并退出。我们没有调整平台原有的恢复阈值或测试断言。记录包含实际请求、响应、原始模型输出和时间线，方便别人检查画面是否与执行一致。”

## 4:30—5:00：结果与局限

“最后读取保存的研究结果。公共异常检测使用 SMD 和 PSM，与刚才的合成 RCA 演示分开。模型评测也保留了低召回、弃权以及防御后的错误引用，没有只展示成功案例。

当前已经完成本地质量和原生链路验证，但人工标签复核、远端 CI、容器与真实集群实验仍没有全部通过。完整材料包含代码、报告、原始输出和失败记录。可交付意味着这些工作能够运行和复核，不意味着尚未取得的证据已经存在。”

## 实际录制命令

下列路径是本次真实执行位置。复现时使用新的输出目录和校验过 SHA256 的本地 GGUF，不能覆盖已有目录。研究模型输出与演示推理分开，演示不会重跑冻结测试集。

```bash
/tmp/aiops-research-venv/bin/python -m demo.record \
  --output /tmp/aiops-video-02 -- \
  /tmp/aiops-research-venv/bin/python -m demo.video_driver \
  --output /tmp/aiops-video-02/run \
  --model /tmp/aiops-research-model/qwen2.5-0.5b-instruct-q4_k_m.gguf

python -m demo.render_video \
  --cast /tmp/aiops-video-02/session.cast \
  --output /tmp/aiops-video-02/aiops-five-minute.mp4 \
  --font /absolute/path/to/NotoSansSC-Regular.ttf
```

`record.py` 输出 asciicast-v2 兼容的时间线，能够由支持该格式的播放器播放；本轮使用的是随包的记录器，没有声称执行过 OBS 或 asciinema CLI。渲染器按原始单调时间戳逐帧显示，不插入假的命令结果；最终视频时长五分钟，进程关闭耗时另记在 recording.json。字体来源及哈希见 `docs/release/font-source.json`。
